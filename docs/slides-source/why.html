This is the working of the agent. It runs in a loop. Look: list the pending transactions and the valid categories. Think: if a merchant is unfamiliar, look up past decisions. Act: propose a category with a confidence, or flag the transaction for a person. Result and feedback: the gate answers with posted, needs_review, or an error, and that answer goes straight back to the agent as feedback, so it can fix its own mistake and retry. People feed back too: the history the agent looks up includes the categories you chose in review. The loop repeats until nothing is pending, up to five rounds per sync. The tools are the only door the model has. Chat is a separate mode with three read-only tools, so the write tools do not exist for it. Guardrails: the gate books automatically only at confidence 0.85 or more and under 500 dollars, which are judgment calls and constants in code today; validation checks the category exists and matches the direction of the money; bank text is untrusted data and the model never supplies amounts or dates; and there is no shell, no files, and passwords stay off the command line. To connect other systems: a bank source implements one method that returns canonical rows, which covers file exports but not paid bank APIs, which also need token renewal, sync cursors and pending versus posted handling. A ledger implements five methods: categories, post, find by number, search and spend report. Akaunting is the worked example, selected by setting three environment variables. The tools are served as standard MCP over stdio, and I have only run them with claude.
